Dokumen Spesifikasi Kebutuhan Pengguna
(User Requirement Specification - URS)

Modul Presensi Biometrik Terintegrasi & Tunjangan Kinerja Kemenag
(SIRITA ZKTeco ADMS & PMA No. 11 Tahun 2019 - Odoo 20)
Penyusun: Tim Pengembang Sistem Informasi Terpadu (SIRITA) | Institut Agama Islam Negeri (IAIN) Parepare
Tanggal Dokumen: 23 Oktober 2026 | Versi: 1.0 (Final Official Release)
Ringkasan Eksekutif:
Dokumen Spesifikasi Kebutuhan Pengguna (User Requirement Specification / URS) ini menetapkan kebutuhan operasional, fungsional, dan non-fungsional untuk modul SIRITA ZKTeco & Tukin pada platform ERP Odoo 20 di IAIN Parepare. Modul ini mengotomatiskan penerimaan log presensi biometrik secara langsung (real-time HTTP Push ADMS) dari perangkat keras mesin sidik jari/wajah ZKTeco di seluruh gedung kampus, pencocokan cerdas (smart-matching) antrean ID mesin ke data induk aparatur sipil negara (ASN) / pegawai, pemrosesan keterlambatan dan kepulangan cepat, hingga penerbitan matriks rekapitulasi Tunjangan Kinerja (Tukin) bulanan resmi berbasis Peraturan Menteri Agama (PMA) No. 11 Tahun 2019.

1. Pendahuluan

1.1 Latar Belakang

Pengelolaan kehadiran kerja pegawai negeri sipil dan tenaga honorer di lingkungan IAIN Parepare sebelumnya menghadapi kendala rekonsiliasi manual antara data log mesin absensi fisik di berbagai gedung fakultas dan rektorat dengan pelaporan tunjangan kinerja kementerian. Dengan implementasi protokol ZKTeco ADMS (Automatic Data Master Server), mesin absensi di seluruh titik lokasi kampus bertindak sebagai klien mandiri yang mendorong (push) log kehadiran setiap detik melalui HTTP ke endpoint terpusat Odoo. Selanjutnya, sistem mengkalkulasi kehadiran secara matematis berdasarkan regulasi PMA No. 11 Tahun 2019 guna menghasilkan potongan kehadiran yang transparan, akuntabel, dan bebas manipulasi.

1.2 Tujuan Sistem

  1. Mengintegrasikan seluruh mesin absensi biometrik ZKTeco di kampus ke server ERP Odoo 20 tanpa memerlukan perantara perangkat lunak pihak ketiga (middleware).
  2. Menyediakan antrean sinkronisasi (User Queue) cerdas untuk memetakan PIN mesin ke profil master pegawai (hr.employee) secara presisi tanpa duplikasi (zero-hallucination).
  3. Menghitung persentase pemotongan kehadiran (TL1 s.d TL4 dan PC1 s.d PC4) secara otomatis terhadap Pagu Tukin Kelas Jabatan (Grade 1 s.d 17).
  4. Mengakomodasi klausul khusus dosen sesuai regulasi Kemenag: Dosen non-sertifikasi dipotong 50% dari pagu tukin grade, dan Dosen bersertifikasi (Serdos) menerima selisih lebih antara Tukin dan Tunjangan Profesi Dosen (TPD).
  5. Menghasilkan dokumen cetak resmi Laporan Rekapitulasi Tukin Bulanan bergaya matriks Excel (Landscape) lengkap dengan tanda tangan pejabat Rektor dan Kepala Biro.

2. Karakteristik Pengguna (User Characteristics)

  • Pegawai / ASN (Pengguna Akhir): Melakukan transaksi presensi biometrik (sidik jari/wajah/kartu RFID) pada mesin absensi di lingkungan kampus dan dapat meninjau rekapitulasi kehadiran mandiri melalui portal.
  • Operator Kepegawaian (HR Officer): Memonitor konektivitas perangkat mesin ZKTeco, mengelola antrean pemetaan user baru dari mesin ke master pegawai, serta memvalidasi keabsahan data presensi.
  • Kepala Bagian Kepegawaian / Analis SDM (HR Manager): Mengatur kelas jabatan (Grade 1--17), memicu proses kalkulasi bulanan Tukin, melakukan verifikasi rekapitulasi, dan mencetak dokumen matriks Tukin.
  • Pejabat Penandatangan (Rektor & Kabiro AUAK): Menerima laporan rekapitulasi final Tukin sebagai dasar otorisasi pencairan tunjangan kinerja bulanan institusi.

3.2 Modul ADMS Endpoint & Perangkat Mesin

Kode Kebutuhan Deskripsi Kebutuhan Kriteria Keberhasilan / Verifikasi
FR-ADMS-01 HTTP Push Ingestion Endpoint Sistem menyediakan controller /iclock/cdata native Odoo yang merespons handshake protokol ZKTeco dengan status HTTP 200 "OK".
FR-ADMS-02 Registrasi Serial Number (SN) Hanya transaksi dari mesin dengan Serial Number yang telah terdaftar aktif pada model zkteco.device yang diproses oleh server.

FR-ADMS-04 Antrean Perintah Perangkat (Commands) Operator dapat memicu perintah tarik user (DATA USER) atau tarik log (DATA ATTLOG) via model zkteco.command.

3.3 Modul Antrean User (User Queue & Smart-Matching)

Kode Kebutuhan Deskripsi Kebutuhan Kriteria Keberhasilan / Verifikasi
FR-MAP-01 Penampungan Data Mesin User baru yang ditarik dari hardware ditampung dalam zkteco.user.queue dengan status new.
FR-MAP-02 Smart Matching Presisi (Bebas Halusinasi) Pemetaan otomatis hanya dilakukan pada data Single Match yang unik 100%. Data nama terpotong yang memiliki lebih dari 1 kandidat diwajibkan konfirmasi manual.
FR-MAP-03 Konsistensi Relasi Presensi Begitu PIN dipetakan ke pegawai (hr.employee), seluruh log absensi masa lalu dan masa depan otomatis terhubung ke pegawai tersebut.

Kode Kebutuhan Deskripsi Kebutuhan Kriteria Keberhasilan / Verifikasi
FR-TUKIN-01 Master Kelas Jabatan & Pagu Tersedia master 17 Grade Tukin sesuai ketentuan PMA 11/2019 (Grade 1 s.d Grade 17).

FR-TUKIN-03 Klausul Khusus Dosen Dosen Non-Serdos menerima 50% pagu grade. Dosen Serdos menerima selisih lebih positif antara Tukin Grade dan TPD (Rp 0 jika TPD >= Tukin).
FR-TUKIN-04 Penerbitan Rekapitulasi Bulanan Model tukin.calculation mengompilasi rekapitulasi seluruh pegawai dan menghitung potongan kehadiran serta Tukin final yang dibayarkan.
FR-TUKIN-05 Cetak Rekap Matriks Landscape Sistem menyediakan template laporan PDF Landscape resmi (Matrix V2) lengkap dengan tanda tangan pejabat Rektor dan Kabiro AUAK.

4. Spesifikasi Kebutuhan Non-Fungsional (Non-Functional Requirements)

  • NFR-PERF-01 (Throughput ADMS): Endpoint HTTP controller ADMS mampu melayani request PUSH secara konkuren dari minimal 20 mesin fisik dengan waktu respons di bawah 200 ms.
  • NFR-PERF-02 (Kecepatan Kalkulasi): Proses perhitungan Tukin bulanan untuk minimal 500 pegawai selesai dalam waktu kurang dari 30 detik.
  • NFR-SEC-01 (Keamanan & Integritas Data): Akses konfigurasi Tukin dan parameter perangkat dibatasi hanya untuk Administrator dan Pengelola Kepegawaian. Log absensi yang telah disahkan ke dalam status Done tidak dapat dimanipulasi oleh operator biasa.
  • NFR-COMP-01 (Kompatibilitas Versi): Modul dirancang murni untuk Odoo 20 (dukungan ORM modern, syntax view XML <list>, dan Python 3.12).
